# Security implementation status
This branch prepares code changes for review; it is not a completed production security rollout.

Implemented: encoded category attribute values; bounded recursive import validation and reserved-key/ID checks; staged backup replacement/merge with persistence before live state changes; import summary removal; JSON/CSV size limits; password-protected AES-256-GCM backups using PBKDF2-SHA256 (600,000 iterations), random 16-byte salts and 12-byte IVs; authenticated restore; legacy import warning and confirmation; warnings for plaintext clipboard export; hash-based script CSP; private resource/cache boundaries; pinned CI actions, timeouts, dependency auditing and Dependabot; privacy/recovery guidance.

Run `npm test`, `npm run test:browser`, `npm audit --audit-level=high` and `node scripts/csp.cjs --check`. After editing inline scripts, regenerate both CSP artifacts with `node scripts/csp.cjs`. The `_headers` file is for hosts supporting that convention; GitHub Pages does not apply it. Meta CSP cannot enforce frame-ancestors. External same-origin scripts remain trusted by policy.

Local Chromium installation failed in the implementation environment; do not interpret unit tests as browser verification.
- Apply `release-controls.json` using GitHub repository administration after the PR check exists. Verify direct pushes and failed checks are rejected. Configuration on disk does not enforce protection. Check applicability/plan support and adjust the check context to the actual workflow status if required.
- Select a dedicated origin and a host with configurable HTTP headers. Configure TLS and the supplied `_headers`, verify actual response headers and foreign-origin framing denial. Do not publish on a guessed domain or silently redirect existing users.
- At the original address, save an encrypted backup and verify recovery in a separate browser profile. Keep the original address available for export. On the new origin restore a backup, compare transaction/category counts and balances, reload and test offline. Do not erase old browser data until verified. Roll back the address without deleting either copy if migration fails.
- Finish the encrypted local vault. Local `moneyAhead.v2` storage remains plaintext in this branch. Required design: explicit setup/unlock with password confirmation and verified recovery backup; versioned AES-GCM envelope, memory-only derived key, serialized asynchronous writes, transactional plaintext migration (delete plaintext only after encrypted-write and decrypt verification), explicit lock and idle lock, reload-to-unlock, quota/error recovery and wrong-password/tamper tests. Do not claim confidential local storage until these are implemented and tested. A PIN screen is insufficient.
- Verify account passkeys/MFA, recovery methods, writers, installed apps/token scopes, secret scanning, private vulnerability reporting and deployment settings through administrative access. These settings cannot be inferred from source.

## Release and rollback
Ralph is the release owner. Keep this branch separate until browser verification and the above rollout gates pass. Merge only through an enforced PR after review. For a code regression, revert the reviewed merge through a tested PR, increment the application cache, and leave browser budget keys untouched. For suspected malicious delivery, stop releases, revoke affected credentials, restore a known-good release, preserve evidence privately and notify affected users with confirmed facts. Never put user budgets or exploit evidence in public issues.
